# 固定 OCR 的结构与翻译评估

本次跑完 62 页、两种模式共 124 次页面处理。结果支持完整对白协议可稳定执行，但尚不支持宣布分组、阅读顺序或翻译语义达到最终目标。v5 A/B 已在分镜候选接入后的同一 62 页 OCR 上重新完成；此前 v4 输出保留作历史对照，不能与 v5 数字混用。

## 可复查证据

运行目录：`.runtime/benchmarks/units-v4-fixed62/`。

- `manifest.json`：62 页源缓存与图片 SHA-256、OCR 和结构指纹，模型名称及摘要。
- `ocr/`：两种模式共用的未翻译副本；原始缓存逐个校验，运行后 62 页均未改变。
- `blocks/`、`dialogues/`：逐页结果；`requests.jsonl` 记录实际推理调用；`records.json` 记录页面耗时。
- `comparison.json`：比较器重新计算 OCR 指纹，核对页面集合、模型、可翻译块、对白成员和顺序，一致性检查通过。
- `layout-report.json`：两种模式全部 62 页的布局计数与轮廓约束检查。
- `panels-v5-report.json`：分镜 v5 在 62 页 OCR 上的只读结构复测；未重新进行 124 次模型推理。
- `sample-audit.json`：第 8 页的视觉与原文对照抽查，含明确失败案例。不是人工打分，也不是全语料标注。
- `renders/`：第 1、12、30、45 页原图、结构层和两组译文截图。
- `implementation.json`：本次 worker、结构、覆盖、显示及运行脚本内容摘要。
- `units-v5-smoke/implementation-v5.json`：v5 小规模回归对应的文件摘要；v4 A/B 目录中的旧 `implementation.json` 仅用于追溯，不能验证当前源码。
- `units-v5-fixed62/`：分镜 v5 下重新完成的 62 页 A/B 结果、清空 OCR 副本和全量布局报告。
- `units-v5-fixed62/quality-report.json`：从现有 A/B 输出汇总的语义风险提示、整句未拆分单元和错误计数；没有重新调用模型。

模型固定为 `qwen3:4b-q6k`，摘要 `8aff527ddd4a49972a33f9d761634c9aac856d7cc7f4acb05352115cb10df272`。A/B 每页从同一份清空翻译的 OCR 副本开始，交替 AB/BA 顺序。A/B 没有更换模型或增大上下文；分镜 v5 复测只验证结构，不代表新的翻译结果。

## 结果

| 自动指标 | 逐块模式（每批 8 块） | 完整对白模式 |
| --- | ---: | ---: |
| 页面数 | 62 | 62 |
| 可翻译原始块 | 627 | 627 |
| 有可用成员译文的块 | 565 | 593 |
| 报告翻译错误的块 | 62 | 16 |
| 可翻译对白单元 | 604 | 604 |
| 完整单元 | 543（89.9%） | 589（97.5%） |
| 只有整句、无逐块映射的单元 | 0 | 9 |
| 总页面处理耗时 | 95.3 秒 | 205.3 秒 |
| 已批准区域中完成布局 | 461/486 | 492/493 |
| 已绘制像素越出批准轮廓（边缘容差 2 像素） | 0 | 0 |

补充的启发式风险计数：逐块模式有 26 个块带语义提示；对白模式有 24 个块、21 个对白单元带提示，另有 9 个 `whole_only` 单元。提示只用于人工复核，不能直接换算成错误率。

v5 `comparison.json` 的 `comparable` 为 `true`；从 `records.json` 重算的页面数、完成单元数、错误块数和耗时分别与 `summary.json` 一致（逐块 62 页/543 单元/62 错误块/95.3 秒；对白 62 页/589 单元/16 错误块/205.3 秒）。

“完整”仅代表当前自动校验认为非空、未报错、非原样返回，且成员结果或整句状态完整。它不等于语义正确。成员留空也可能只是整句无法按现有边界拆分，不能把这些全部算作翻译失败。不同模式的可信局部矩形数量可能不同，因为局部覆盖仍受译文就绪状态影响；OCR 与对白分组已另行核对一致。

## 已确认的缺陷与未通过的门槛

1. 分镜候选现已用于第 8 页的阅读分层，抽查顺序与视觉标注一致；v5 重新运行后仍缺少完整测试集的人工分镜顺序标注，阅读序号连续不代表全语料顺序正确。
2. 第 8 页对白模式成员 7/8 的比较关系翻反，成员 14 的否定含义丢失。格式有效率不能作为中文准确率或连贯性的替代。默认翻译单位暂不切换。
3. 连通气泡的多个叶瓣是否合并尚需明确标注与规则；当前存在应该连续阅读但仍分开的单元。需复核候选不是“分组错误”的同义词。
4. 8 个单元只有整句输出。程序保留整句用于成员完全匹配的可信区域；无可靠拆分时无法在不同小区域逐块回填。`lines_unreviewed` 也只保证字面按行映射，尚未保证语义对应。
5. 像素没有越出批准轮廓，只证明绘制遵守几何限制，不证明轮廓检测正确，更不能声称画面误伤率为零。仍需要标注允许擦除区域并比较。
6. OCR 准确率、分组准确率、人工连贯性和实际误伤率尚无完整标注分母，不能报告百分比。
7. 翻译结果现在会额外记录否定、比较和数量关系的可解释风险提示；这些提示只用于人工复核，不是自动准确率或拒绝规则。
8. 已提供批量人工标注评分脚本；第 8 页仅保留已确认的分镜顺序标注，结果为 3/3（100%）。对白成员归属标注因视觉证据不足而暂缓，`dialogue_exact_mean` 保持为空，不能外推全量准确率。
9. 标注评分还会单独输出顺序无关的 Jaccard 覆盖率、文字块方向/类型字段准确率，以及未知编号、重复归属和空单元等 `label_warnings`；这些指标用于发现标注问题，不能替代严格准确率。
10. 分镜检测依赖 OpenCV；当运行环境未安装 OpenCV 或图像不可读时，程序保留 OCR/对白结构并回退到文字框阅读顺序，同时记录 `panel_error`，基础翻译流程不会中断。

## 本轮修复与验证

完整对白仅在所有成员完全匹配的区域显示；人工编辑、错误或跳过成员会使整句缓存失效。整句无法拆分时不再放进首个 OCR 框，也不再把拆分状态当作模型错误。去重后保留全部块编号，并同步重复成员的映射信息。对白请求的 JSON 目标编号与 schema 一致，不再把错误的逐块响应升级为完整对白。旧逐块缓存不能冒充对白模式的推理结果。

78 项测试通过，包括整句可用但无逐块映射、重复调用命中正确缓存、模式切换保留手改、错误输出键拒绝、精确区域成员匹配、额外未译成员不得被擦除、人工编辑使整句失效、不可信 OCR 框不绘制、源文本变更、OCR 去重、检测器数组倒序、A/B 输入不一致、分镜沟槽切分、图像失效回退及整句语义风险提示等情况。

下一阶段建立更大规模人工结构标注，复测分镜与气泡顺序；随后评估完整对白的语义拆分和翻译质量。整体目标保持未完成。
