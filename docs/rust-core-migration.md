## 实施与验收顺序

1. 冻结源代码、图像、译文与显示基线，采集 Python 基准。
2. 建立原生 OpenCV 与 Rust 构建、受控常驻模型进程协议。
3. 移植图像、几何与清字算法，逐页对照区域、蒙版和修补像素。
4. 移植翻译协议、结果校验、缓存与任务控制，使用固定请求/响应验证既有语义；保留手工修改。
5. 接入独立 macOS 候选应用，验证取消、快速换页、编辑刷新和失败恢复。
6. 35 页完整对照与性能测试后提交报告；效果回退、未实现职责和未验证项目必须显式列出。

## 性能口径

- 初次显示生成：预装相同模型，独立空显示缓存；包含进程启动、必要模型加载、分析、修补、编码与结果传输。
- 持久缓存复用：同一组输入、已生成显示缓存，重复三轮；与首次生成单独汇总。
- 系统文件缓存不强制清空，因此不能称为物理磁盘冷启动。
- 测量与编译任务分开进行；记录每页耗时、整章总耗时、进程内存指标及运行环境。
- 使用现有译文作固定输入，隔离语言模型输出随机性；显示性能不冒充 OCR 或翻译推理性能。
- 同时检查译文、原图与原始缓存不变，244 段已有译文完整显示，字形越界与文字丢失为零。最终图像还须目视复核。

本机私有工件位于 `.runtime/rust-migration/`；`pages.json` 保存样本哈希、缓存副本和基线图路径。

## 已完成的基础验证

- Python 显示基线：35 页独立空资产缓存首次生成合计 98.035 秒，单页中位数 2.027 秒；已生成缓存三轮共 105 次，单页中位数 0.1255 秒。仅为本机基线，不是 Rust 提速结果。
- 35 页原图、原始译文和测试副本哈希保持一致；三轮缓存结果与首次生成的结构化输出一致。
- Rust 管理的常驻模型接口：第 13、14、20、23 页检测蒙版，以及每页选定的真实修补裁剪，与原实现逐像素相同。这不代表完整 35 页原生流程已经通过。
- 握手、退出、错误请求恢复、数组形状与目录边界检查通过；Rust 请求超时后拒绝复用旧响应通道的测试通过。
- 原生 OpenCV 4.11.0 在任务目录编译，35 页 BGR 解码像素与旧版完全相同；没有安装系统级库。
- 分镜、对话分组、阅读顺序、缓存签名、译文同步已由 Rust 实现。35 页各执行首次重建、带图复用、无图复用；连同旧版行为案例共 139 次差分比较一致。18 个行为测试通过，另一个依赖未安装 Windows 样本的案例跳过；Python 导入失败测试不适用于原生库，单独排除。
- 差分检查比较完整页面 JSON，包含旧译文和诊断字段。启用 JSON 浮点往返解析，防止读取旧缓存时改变耗时等小数。原图、原始缓存及输入副本哈希未改变。
- 显示框裁剪、疑似页码保留、独立竖排长划线补全已移植。35 页全部显示框及补全蒙版像素哈希一致；加上前置长划线、尾部长划线、画面线条拒绝扩展、手工校正页码等案例，共 43 次差分比较通过，3 个笔画行为测试通过。只使用预先生成的检测蒙版，没有再次调用模型。
- 前述记录是模块级验证；下方记录完整显示生成与离线整页绘制的验收。候选应用集成和性能对比仍未完成。
- 气泡和旁白几何：35 页及 12 组形状/边界案例对照通过，包含轮廓顶点、填充蒙版哈希、内部排版矩形、局部擦除多边形和旧缓存边界。验证了窄颈连体气泡分离、同椭圆双列不拆分、灰底气泡、底部截断气泡、分格线阻止旁白合并、插画阻止背景被当成旁白空地，以及暗底旁白。
- 清字蒙版：35 页加 8 组有/无检测蒙版、普通/网点/暗底/穿越线条案例，共 221 个修补区域，裁剪、原始灰度像素、允许修改蒙版、最终清字蒙版、纹理标记均与 Python 一致。测试使用恒等修补回调，仅校验蒙版和路由；没有运行 LaMa，因此不代表修补像素或最终显示已经验收。

- OCR 后区域分类：`overlay.rs` 已替代旧 `backend/overlay.py` 的候选区域、片段合并、局部填充、短语气词与缓存签名规则。35 页首次重建/缓存命中/无图/清空机器译文的 140 次对照，加既有形状与异常 OCR 框案例，共 176 次严格 JSON 对照通过。旧 10 项行为测试中 9 项通过，1 项 Windows 专属样本缺失而跳过。保留整数与浮点坐标类型，避免下游对白结构签名产生无效变化。

- 原子保存使用同目录临时文件与替换，文件权限为 0600；CLI 已验证逐批结果、进度和指标写入。4 项 Rust 单元测试通过，包括替换后内容/权限/临时文件清理以及模型超时旧响应隔离。
- 视觉图片输入：`vision_image.rs` 以 Rust 实现旧 Pillow RGB 缩略图的 Lanczos 系数、定点取整和整数预缩小；`vision_decode.rs` 处理颜色模式与 EXIF 方向。OpenCV 原生构建补齐 TIFF；一个小型 C ABI 桥只暴露现有 libjpeg 的 CMYK 原始采样，颜色转换仍由 Rust 完成。35 页及 56 个大图/极窄图/PNG/JPEG/WebP/BMP/TIFF/EXIF 八方向/CMYK/调色板/透明/16 位及浮点灰度案例的最终 JPEG 字节全部相同。没有把图片编码留在 Python。Pillow 派生缩放规则的许可已保存在 `core/LICENSES/Pillow.txt`。
- 完整视觉翻译：`vision_pipeline.rs` 实现独立视觉缓存初始化、配置变化失效、8 块分批、整页图片上下文、Han 共用词回声提示、OCR 修正建议、原文不自动替换、失败移除旧建议、50 条运行记录上限及逐批原子保存。35 页首次处理和缓存复用，加异常回复、模型/接口/原文变化等共 100 组场景通过；另有 3 次缓存初始化检查，合计 103 次原生调用、117 次模拟生成请求。完整 HTTP 请求（含 JPEG 与提示词）、最终页、每次保存快照和除时间值外的指标均与旧版一致。CLI `translate --vision` 已验证独立输出和手工译文保护。
- 图片兼容修复后，15 项阅读显示行为测试再次通过；新增损坏 JPEG 的 C 边界错误返回及截断 EXIF 元数据边界测试。仍未对真实语言模型重新生成译文，因此这些结果证明输入/协议/持久化一致，不是新一轮模型质量评测。
