# Rust 重构：35 页对照验收

本次已将当前 macOS 阅读器的业务核心迁入 Rust，保留 Swift 界面、中文排版和绘制，Python 仅运行已安装的文字检测、Manga OCR 和 Anime LaMa 模型。候选版保存在独立分支 `refactor/rust-core`，稳定版基线为 `a08b421` / `stable/pre-rust-20261108`，没有合并或覆盖稳定版。

## 交付与使用

- 候选应用：`macos/dist/Koma Rust 候选版.app`。
- 本地构建/运行：`./macos/scripts/build_and_run.sh --verify`；该命令只重启当前候选应用，检查启动后持续存活。
- 候选数据：`~/Library/Application Support/KomaReaderRust`，包含独立页面、显示缓存和 `config.json`。
- 首次读取稳定版连接配置并保存独立副本，权限 0600；API Key 不进入命令行、页面缓存、指标或 Python 推理进程。没有钥匙串读取。
- 原稳定应用、原始漫画和译文缓存保持可用。需要回到原版时退出候选版，打开原 `Koma 漫画翻译.app` 即可；无需撤销或恢复原数据。

候选应用使用此 checkout 的 Rust 可执行文件、原生依赖和 Python 模型环境，属于本机开发交付，尚未制作可脱离项目目录分发的安装包。

## 职责归属

| 功能 | 实现 |
|---|---|
| 页面哈希、缓存复制/原子保存、编辑校验 | Rust |
| 跨页队列、取消、单句重试、故障恢复 | Rust |
| 推理进程、自有本地 Ollama 生命周期 | Rust |
| 分镜、对白分组、阅读顺序、区域与清字规则 | Rust / 原生 OpenCV |
| 图像解码、视觉输入编码、修补合成、PNG 输出 | Rust / 原生库 |
| oMLX/Ollama HTTP、提示词、响应校验、翻译批处理 | Rust |
| CTD、Manga OCR、LaMa 推理及模型预处理 | 常驻 Python 适配器 |
| 阅读界面、中文断行与绘制 | Swift |

候选阅读器不通过 Rust 启动旧 Python 业务 worker。原 Python 实现作为稳定版和差分测试参照保留。

## 显示性能

同一台机器、相同 35 页与既有译文、相同已安装模型，独立空显示缓存首次生成，然后三轮缓存复用。编译和测试检查不计入处理时间，没有强制清空系统文件缓存。

| 指标 | Python 稳定版 | Rust 候选核心 |
|---|---:|---:|
| 35 页首次生成，含服务启动 | 98.035 秒 | 47.243 秒 |
| 首次生成单页中位数 | 2.027 秒 | 0.705 秒 |
| 缓存命中 105 次总计 | 13.259 秒 | 0.751 秒 |
| 缓存命中单页中位数 | 125.49 毫秒 | 6.54 毫秒 |

首次生成整章约快 **2.1 倍**，缓存命中单页中位数约快 **19.2 倍**。Rust 总时间包含 0.823 秒服务启动，另包含客户端 JSON 解码。稳定版每页启动处理进程，候选版复用常驻服务与推理进程，所以收益包含进程复用和缓存设计，不能全部归因于语言本身。

上述数字衡量显示处理，不代表 OCR 或语言模型推理提速，也不包含界面绘制时间。单机单组样本结果不等于所有漫画、硬件或负载下的保证。

## 内存与退出

原生服务延迟启动推理进程，复用检测/修补模型；翻译请求前释放 OCR 对象，应用退出时关闭所属模型进程。取消或超时导致模型通道中断时，清理旧进程与临时目录，后续操作使用新通道。显示缓存命中无需推理进程。

本轮 Rust 服务及所属推理进程的 RSS 合计采样最高约 **9.77 GiB**。稳定版 `time -l` 单页最高 RSS 约 **11.54 GiB**，但统计口径不同，不能据此宣称内存降低。常驻模型会持续占用内存直至释放/退出，属于当前复用策略的代价。

Rust 仅管理自己启动的本地 Ollama 进程组和 runner。已存在的服务、带密钥或其他地址的服务以及 oMLX 只进行正常接口访问，不被接管、终止或改变配置。本地启动测试使用临时模拟程序及随机端口，没有操纵现有模型服务。

## 启动问题闭环

正式入口曾因 `UserDefaults(suiteName: 自身应用标识)!` 返回空值而启动崩溃。已改为由候选 bundle identifier 隔离的 `.standard`，移除该强制解包。修复后正式应用持续运行，实际窗口正常显示漫画并连接现有 oMLX；稳定配置内容和权限未变，候选配置为独立 0600 副本。启动脚本增加 10 秒持续存活检查，避免把瞬间出现的进程误报为成功启动。
